# AI Supplier Template Mockup Plan

## Summary

Upgrade the current fixed platform-template mockup flow into supplier-aware template matching for AI-generated product artwork.

The target flow remains inside Phase 2A + Phase 2B:

```text
AI design image
-> supplier print file
-> supplier/product/variant/view matched mockup
-> product draft
```

This plan does not include 3D mockups, cloth physics, marketing automation, or advanced multi-supplier routing.

## Key Changes

- Template selection should prefer the most specific supplier context:
  - `supplier_product_id + supplier_variant_id + print_position/view_id`
  - `supplier_product_id + print_position/view_id`
  - `platform_product_id + print_position`
  - existing first active platform design template fallback
- Keep `print_file_url` production-focused:
  - transparent PNG
  - dimensions from `supplier_print_spec.print_file_width` and `print_file_height`
  - suitable for supplier upload or quick product creation
- Keep `mockup_image_url` storefront-focused:
  - generated by placing the AI design onto a supplier clothing background
  - dimensions from the selected design/mockup template
  - fallback to placeholder if the background image cannot be loaded
- Preserve the current public AI worker response fields:
  - `design_image_url`
  - `print_file_url`
  - `mockup_image_url`
  - `title`
  - `description`
  - `tags`
  - `seo`
  - `price_suggestion`

## Implementation Notes

- Extend or complement the current template data with supplier-aware fields:
  - `supplier_product_id`
  - `supplier_variant_id`
  - `view_id`
  - `color`
  - `size`
  - `preview_background_url`
  - `design_area_x`
  - `design_area_y`
  - `design_area_width`
  - `design_area_height`
- Update Medusa supplier product responses so AI worker can resolve the correct template from `/store/supplier-products`.
- Update AI worker `MedusaClient.resolve_supplier_context()` so it does not blindly choose `design_templates[0]`.
- Keep Pillow-based 2D composition for the current phase:
  - load AI design as RGBA
  - resize into the target design area
  - paste into transparent print canvas for production file
  - paste into clothing background for mockup image
- If S2BDIY later returns a supplier-generated product mockup from product detail, prefer that supplier mockup over the locally generated preview.

## Test Plan

- AI worker tests:
  - exact variant template is selected when available
  - supplier product template is selected when variant template is missing
  - platform template is selected as fallback
  - missing or failed background URL still generates a mockup
  - print file output size matches supplier print spec
- Medusa tests:
  - `/store/supplier-products?platform_product_id=pp_tshirt` returns print specs and template data
  - template data remains store-safe through existing store context rules
  - supplier product and variant metadata remain available for line item production metadata
- Validation commands:
  - `npx.cmd tsc --noEmit -p apps/medusa-backend/tsconfig.json`
  - `npm.cmd --workspace apps/medusa-backend run db:migrate`
  - `npm.cmd --workspace apps/medusa-backend run seed`
  - `AI_WORKER_MOCK_GENERATION=true pytest -q` from `apps/ai-worker`

## Assumptions

- Current phase uses 2D flat mockup composition only.
- Supplier print specs remain the source of truth for production file size.
- Supplier or variant-specific templates are preferred when present, but missing template data must not block product draft creation.
- Existing AI worker and Medusa API response shapes stay backward-compatible.
